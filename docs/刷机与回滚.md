# 刷机与回滚指南 · 红米 K60 (mondrian)

> ⚠️ **先做这一步，其它都往后放**：备份你当前的原厂 `boot.img`，刷坏了能立刻救回来。

---

## 零、刷机前准备

### 1. 备份原厂 boot.img（最重要）

手机需已解锁 BL、已开 USB 调试。电脑装好 `adb` / `fastboot`（platform-tools）。

```bash
adb devices                 # 确认能识别
adb reboot bootloader       # 进入 fastboot
fastboot devices            # 确认能看到设备
```

红米 K60 是 **A/B 双分区 + 动态分区**，先确认当前槽位：

```bash
fastboot getvar current-slot
# 返回 a 或 b
```

导出当前两个槽位的 boot 分区（保险起见两个都留）：

```bash
fastboot getvar current-slot
# 假设返回 a：
fastboot fetch boot_a boot_a_stock.img
fastboot fetch boot_b boot_b_stock.img
```

> 如果你的 fastboot 版本不支持 `fetch`，用 **fastbootd** 或任何"分区备份"工具，
> 也可以直接从你当前 ROM 的官方线刷包里取 `boot.img`（推荐，最稳）。
> **备份文件务必放到电脑上，别只放手机里。**

### 2. 关闭 AVB 校验（刷自定义内核必须做）

刷非官方签名的 boot 会让 AVB 校验失败、卡在开机 logo：

```bash
fastboot --disable-verity --disable-verification flash vbmeta vbmeta.img
```

`vbmeta.img` 可以从你 ROM 的官方线刷包里取（和 boot.img 同一个包）。

> 有些机型刷了自定义内核后仍会红字警告 `dm-verity`，那是正常的；
> 只要不卡 logo 就没问题。部分 ROM 需要在刷完后 `fastboot -w`（会清数据，想清楚）。

## 一、刷入内核（3 种方式，按推荐顺序）

从 Actions 的 Artifacts 下载 **`K60-AnyKernel3`**，解压得到 `K60-mondrian-KernelSU-BBG-*.zip`。

### 方式 A：KernelSU / 内核管理器 App 直刷（最简单）

本项目 **SukiSU 是编进内核的**（`CONFIG_KSU=y`），不依赖 ramdisk 补丁，
所以任何"内核刷写"类 App 都能直接用：

1. 把 zip 传到手机
2. 用内核刷写 App（如 KernelFlasher / EX 内核管理器 / 面具类工具的"刷入镜像"功能）
3. 选择该 zip，刷入 boot 分区
4. **不要**选"重打包 ramdisk / 二次 patch"

### 方式 B：临时启动 TWRP 后刷卡刷包（最通用）

K60 没有独立 recovery 分区，用 `fastboot boot` 临时启动：

```bash
fastboot boot twrp-mondrian.img     # 用适配 mondrian 的 TWRP
# 进入 TWRP 后：Install -> 选 K60-mondrian-KernelSU-BBG-*.zip -> 滑动刷入
# 刷完 Reboot System
```

> AnyKernel3 会自动识别 A/B 槽位、校验设备代号是否为 `mondrian`。
> 如果报 "device mismatch"，说明你的机型代号不是 mondrian，**立刻停下**。

### 方式 C：手动打 boot.img 再用 fastboot 刷（最可控）

```bash
# 在 Linux/WSL 里用 AnyKernel3 自带的工具
unzip K60-mondrian-KernelSU-BBG-*.zip -d ak3
cd ak3
./tools/magiskboot unpack ../boot_a_stock.img      # 解出 kernel / ramdisk
cp /path/to/Image.lz4 kernel                        # 换成新内核
./tools/magiskboot repack ../boot_a_stock.img boot-new.img
```

```bash
fastboot flash boot_a boot-new.img
fastboot flash boot_b boot-new.img     # A/B 建议两个都刷，或至少刷当前槽
fastboot reboot
```

## 二、开机后验证

```bash
adb shell uname -r                    # 应看到 5.10.81-gki...
adb shell su -c id                    # SukiSU 生效的话能拿到 root
```

SukiSU 管理器 App（[SukiSU-Ultra Releases](https://github.com/SukiSU-Ultra/SukiSU-Ultra/releases)）
装上后应显示"已安装 / 工作中"。

BBG 生效检查：

```bash
adb shell su -c 'dmesg | grep -i baseband'
adb shell cat /sys/kernel/security/lsm     # 应能看到 baseband_guard
```

## 三、USB 无线网卡（可选）

额外驱动是 `=m` 模块，**不会自动加载**。下载 `K60-extra-modules` artifact，
把 `.ko` 推到手机后手动加载：

```bash
adb push r8188eu.ko /data/local/tmp/
adb shell su -c 'insmod /data/local/tmp/r8188eu.ko'
adb shell su -c 'dmesg | tail -20'
```

想开机自动加载，建议做成 KernelSU 模块：

```
/data/adb/modules/k60-net-modules/
├── module.prop
├── post-fs-data.sh      # 里面写 insmod 命令
└── system/              # 或直接把 .ko 放这里
```

`post-fs-data.sh` 示例：

```sh
#!/system/bin/sh
MODDIR=${0%/*}
for m in r8188eu rtl8xxxu rt2800usb ath9k_htc mt7601u; do
  [ -f "$MODDIR/$m.ko" ] && insmod "$MODDIR/$m.ko"
done
```

## 四、回滚（刷坏了怎么办）

### 情况 1：能进 fastboot（绝大多数情况）

```bash
fastboot flash boot_a boot_a_stock.img
fastboot flash boot_b boot_b_stock.img
fastboot reboot
```

### 情况 2：卡 logo / 黑屏，但 fastboot 还在

同上。**不要**急着 `fastboot -w`（清数据），先刷回 boot 试试。

### 情况 3：连 fastboot 都进不去

用小米官方线刷工具（MiFlash）刷完整官方包，选 **"保留数据"** 模式；
实在不行只能清数据。

## 五、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 卡在开机 logo | AVB 未关 / 内核与 ROM 不匹配 | 关 AVB；或换匹配你 ROM 版本的内核 |
| 能开机但 Wi-Fi 打不开 | 厂商模块加载失败 | 见下方"模块加载失败" |
| 刷机时报 device mismatch | 机型不是 mondrian | 确认机型，别硬刷 |
| 没有 root | SukiSU 管理器版本不匹配 | 换与 `ksu_ref` 对应的管理器版本 |
| 开机后 `/sys/kernel/security/lsm` 没有 baseband_guard | BBG 未生效 | 检查构建时 `enable_bbg` 是否为 true |

### 模块加载失败怎么查

```bash
adb shell su -c 'dmesg | grep -iE "version magic|disagrees about version|Unknown symbol"'
```

- 出现 `disagrees about version of symbol` → **符号 CRC 不匹配**（说明内核改动破坏了 KMI）
- 出现 `version magic ... should be` → vermagic flag 段不匹配（说明 `MODVERSIONS`/`MODULE_UNLOAD`/`PREEMPT` 被改动了）

本项目的 `configure.sh` 会对这三个配置项做强校验，正常情况下不会出现第二种。

## 六、务必知道的一点

你手机 ROM 里的厂商模块（Wi-Fi / 蓝牙 / 触控 / 音频）是**预编译**的。
本项目用小米官方开源内核（5.10.81）构建，而你的 ROM 可能是更新的 5.10.x。
由于内核的 `same_magic()` 在模块带 CRC 时**忽略版本号**，只比较 flag 段，
所以正常情况下模块能正常加载 —— 但**前提是你没有破坏 KMI 符号**。

如果你的 ROM 是较新的 HyperOS，刷完发现 Wi-Fi 等异常，请先确认：

```bash
adb shell uname -r          # 你原厂内核版本
adb shell getprop ro.build.version.incremental
```

把这两个值记下来，方便判断是"ROM 版本差异"还是"内核本身有问题"。
